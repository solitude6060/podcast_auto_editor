## Gemini Review

**Verdict:** REQUEST CHANGES

### Findings

#### CRITICAL
- **`diarization.py:189,196`** — `raise DiarizationProviderError(...) from exc` chains the underlying exception. Network library exceptions on 401/403 frequently embed authorization headers or URL parameters. If `HF_TOKEN` appears in the chained exception message, it leaks through traceback to the terminal.
  - Recommended fix: `from None` on all auth/load-error raise paths.

#### MEDIUM
- **`diarization.py:183`** — `if "403" in err_str or "license" in err_str.lower() or "access" in err_str.lower()` is brittle; downstream changes to `pyannote` or `huggingface_hub` error wording break routing.
  - Recommended fix: collapse to single "auth/license" bucket pointing at runbook URL and mentioning both license acceptance and `HF_TOKEN`.
- **`tests/test_diarization.py:341`** — Sentinel test only checks `str(exc_info.value)`, missing `__cause__` and formatted traceback. Test falsely passes even with the `from exc` bug present.
  - Recommended fix: assert `exc_info.value.__cause__ is None` and format full traceback, check sentinel absent from entire trace string.

### Risk Callouts
- Token non-leakage: **FAILS** — `from exc` chaining violates the traceback non-leakage invariant.
- Error path semantics: **FAILS** — string-matching collapse needed.
- Lazy import, pipeline caching, normalization flow-through, `pyproject.toml`, CLI surface, AGENTS.md gate: all PASS.

## MiniMax Review

### Findings

#### MEDIUM
- **`diarization.py:178`** — The 403/license/access/forbidden multi-branch string match is fragile. If pyannote raises a differently-worded gated-repo exception, the error falls through to the generic 401 bucket producing a less-actionable message.
  - Suggested fix: collapse to a single "auth/license" bucket matching all known auth keywords and directing user to `_LICENSE_URL` with a note to ensure `HF_TOKEN` is set and valid.

### Risk Callouts

- One behavioral note: `confidence` is hardcoded to `0.0`; real pyannote turn scores silently discarded. Not a bug per plan, but flag for a future PR if per-speaker confidence is needed.

## Codex Review

**Verdict:** BLOCK

### Findings

#### CRITICAL
- **`diarization.py:188-202`** — Auth/model-load errors re-raised `from exc`. Python chained tracebacks print the original exception. If pyannote/HF includes the token in underlying exception text (e.g., request URL, header value on 401/403), the token leaks through traceback, violating PR-C2's critical invariant.
  - Recommended fix: `raise DiarizationProviderError(...) from None` on all provider-load/auth error paths. Add a regression test that makes fake `Pipeline.from_pretrained()` raise `OSError(f"401 unauthorized: token={SENTINEL}")` and asserts formatted traceback + `str(exc)` + `str(exc.__cause__)` do not contain the sentinel.

#### MEDIUM
- **`diarization.py:189-201`** — `"access"` appears in both license-restricted errors ("Access to model … is restricted") and missing-token errors ("make sure you have access to …"), causing misclassification. Collapse to one bucket.
- **`test_diarization_pyannote_real.py:111-126`** — Plan requires env-gated two-speaker clip with exactly two distinct labels, and a one-speaker fixture with exactly one label. Implementation has no two-speaker real test; one-speaker silence test uses `<= 1`, permitting zero segments. Update plan with an explicit deferral decision or add fixtures.

#### LOW
- **`cli.py:167`** — `--provider pyannote` help text says "deferred to PR-C2" but this PR lands PR-C2. Update without adding new flags.

### Risk Callouts
- Token non-leakage: gap in traceback/cause leakage from `from exc`; sentinel tests do not assert formatted traceback or `__cause__`. **Blocking gap.**
- Auth/license string matching: brittle, misclassification risk on 401 "access" wording.
- Lazy import, pipeline caching, normalization flow-through, `pyproject.toml`, AGENTS.md gate: PASS.
- Two-speaker real test: absent (plan §4 requirement); one-speaker assertion permits zero segments.
